# ClaudSoul Skill Contract

> Контракт SKILL.md — обязательные требования к скиллам системы.
> Источник вдохновения: levnikolaevich/claude-code-skills skill_contract.md

## Обязательная структура

Каждый SKILL.md должен содержать:

| Элемент | Требование |
|---------|-----------|
| YAML frontmatter | `name`, `description` (≤200 символов), `user-invocable` |
| `**Type:**` | один из: `worker` · `coordinator` · `orchestrator` · `reference` (см. ниже) |
| `## Definition of Done` | Чекбоксы `- [ ]` — критерии завершения |
| `**Version:** X.Y.Z` | В конце файла |
| `**Last Updated:** YYYY-MM-DD` | В конце файла |

## Запрещено

| Что | Почему |
|-----|--------|
| Пассивные ссылки (`See X`, `Per Y`) | Агенты их не загружают |
| `**Changes:**` секции | Используй Version + Last Updated |
| `> 400 строк` в SKILL.md | Token efficiency — выноси в references/ |
| description с `:` без кавычек | Сломает YAML парсер |

## Ссылки на файлы

Если скилл зависит от внешнего файла — используй:
```
**MANDATORY READ:** Load `~/.claude/global-lessons/META.md`
```

НЕ используй:
```
Read META.md first.          ← пассивная ссылка, может быть проигнорирована
See META.md for details.     ← ещё хуже
```

## Типы скиллов

Большинство скиллов — `worker`, но архитектура L1/L2-маршрутизации добавила ещё три
типа. `Type:` объявляет роль (используется `skill-review` при валидации):

| Type | Роль | Примеры |
|------|------|---------|
| `worker` | Standalone-исполнитель: делает одну задачу, вызывается напрямую | `/retro`, `/learn`, `/save`, `/decompose` |
| `coordinator` | Маршрутизатор: направляет к под-функциям/другим скиллам | `/knowledge` |
| `orchestrator` | Ведёт многошаговый процесс, может запускать агентов/скиллы | `/pipeline`, `/project-health` |
| `reference` | Методичка/справка: грузится по надобности, не «исполняет» | `/trajectory-prediction` |

## Независимость (worker)

`worker`-скиллы — standalone:
- Нет `**Parent:**`, `**Coordinator:**` обратных ссылок на вызывающего
- Каждый можно вызвать напрямую

`coordinator`/`orchestrator` по своей роли ССЫЛАЮТСЯ на другие скиллы (это их работа) —
для них запрет обратных ссылок не применяется. `reference` — пассивный документ, не
исполнитель: требования к DoD-чекбоксам у него номинальны (это справка, а не воркер).

## Definition of Done — формат

```markdown
## Definition of Done

- [ ] [Конкретный проверяемый результат]
- [ ] [Файл создан/обновлён по пути X]
- [ ] [Отчёт показан пользователю]
```

Чекбоксы — не пожелания, а gate: скилл не завершён, пока все не выполнены.
