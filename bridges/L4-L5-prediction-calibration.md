# Мост L4↔L5: Калибровка предсказаний

> Навык: отслеживать КАК ХОРОШО предсказываешь и подстраивать подход.

## Зачем

Без этого моста предсказания — black box. Система предсказывает, но не знает, улучшается ли она. С мостом — каждое предсказание порождает метаданные: точность, тип промаха, что помогло угадать. Это позволяет КАЛИБРОВАТЬ confidence и УЛУЧШАТЬ методологию.

**Ценность:** Самоулучшающиеся предсказания. Не "предсказывать и надеяться", а "предсказывать, измерять, корректировать".

## Цикл

```
L4 (Trajectory)             L5 (Meta-Cognition)          L4 (Trajectory)
┌──────────────┐            ┌──────────────┐             ┌──────────────┐
│ Предсказания │──accuracy→ │ "Предсказания│──правило──→│ Изменённая   │
│ + результаты │            │ по типу X    │             │ методология  │
│              │            │ точны на 80%,│             │ предсказаний │
│              │            │ по типу Y 20%│             │              │
└──────────────┘            └──────────────┘             └──────────────┘
       ↑                                                        │
       └──────────── лучшие предсказания ───────────────────────┘
```

## Что даёт

| Без моста | С мостом |
|-----------|----------|
| Предсказания = intuition | Предсказания = calibrated model |
| Одинаковый confidence для всех типов | Confidence адаптирован по типу задачи |
| Нет понимания "в чём я хорош/плох" | Ясная карта сильных/слабых сторон prediction |

## Реализация

1. **В SESSION.md Predictions:** уже есть таблица (predicted, actual, accuracy). Формализовать: `prediction_type` (topic, reaction, need, action)
2. **В metrics-collector:** агрегация accuracy по типам предсказаний за 5+ сессий
3. **В /knowledge-audit:** секция "Prediction health" — accuracy by type, trend, weakest area
4. **В правилах:** если accuracy по типу < 40% → снизить confidence для этого типа; если > 80% → повысить
